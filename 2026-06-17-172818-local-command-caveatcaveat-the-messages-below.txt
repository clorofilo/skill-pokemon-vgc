  ## Análisis de opciones                                                       
                                                                                
  Para dotar al entorno de capacidades avanzadas en análisis de Pokémon         
  competitivo, se contemplan dos vías de implementación técnica:                
                                                                                
  ### 1. Estructura de una Skill Personalizada (Markdown)                       
                                                                                
  Se puede crear un archivo `.md` (por ejemplo, `pokemon-vgc.md`) en el         
  directorio de *skills* del proyecto para guiar el razonamiento del modelo     
  ante problemas de *teambuilding* o cálculo de daños.                          
                                                                                
  ```markdown                                                                   
  # Skill: Análisis de Pokémon Competitivo (VGC / Smogon)                       
                                                                                
  ## Contexto                                                                   
  Asistir en la optimización de equipos, análisis de sinergias y cálculo de     
  'spreads' de EVs bajo normativas oficiales.                                   
                                                                                
  ## Directrices de Decisión                                                    
  1. Priorizar siempre los 'Speed Creeps' relevantes del formato actual antes   
  de asignar EVs defensivos.                                                    
  2. Evaluar la cobertura de tipos ofensiva y defensiva mediante matrices de    
  resistencias.                                                                 
  3. Considerar el control de velocidad (Trick Room, Tailwind, Icy Wind) como   
  factor crítico.                                                               
                                                                                
  ## Anti-patrones                                                              
  - Sugerir distribuciones de 252/252/4 sin justificación matemática en         
  formatos de dobles (VGC).                                                     
  - Ignorar habilidades clave o mecánicas activas del formato                   
  (Teracristalización, etc.).                                                   
                                                                                
  ```                                                                           
                                                                                
  ### 2. Integración con Herramientas Externas (Model Context Protocol - MCP)   
                                                                                
  Para obtener un rendimiento óptimo con datos en tiempo real, se recomienda    
  conectar el modelo a fuentes de datos mediante servidores MCP.                
                                                                                
  * **Integración con Showdown:** Desarrollar o conectar un servidor MCP local  
  que consuma la API de *Pokemon Showdown* o los archivos de datos de           
  `smogon-usage` para inyectar estadísticas de uso actualizadas, *sets* más     
  comunes y viabilidad de la viñeta (*tier list*).                              
  * **Cálculo de Daño Automatizado:** Programar una herramienta personalizada   
  (*custom tool*) en Python o TypeScript que use la librería `@smogon/calc`     
  para ejecutar simulaciones exactas de daño directamente desde la terminal de  
  comandos."

● ---
  Tres enfoques arquitectónicos

  ---
  Enfoque A — Monorepo integrado (Recomendado)

  vgc-app/
  ├── skill/          # Markdown skill para Claude Code
  ├── mcp-server/     # TypeScript: servidor MCP + cache Showdown
  ├── calc-tools/     # Python: cálculo de daño, EV optimizer
  ├── data/           # Cache local JSON (smogon usage, sets)
  └── memory/         # Archivos de sesión SDD entre sesiones

  El MCP server expone tanto los datos de Showdown como herramientas que llaman
  a los scripts Python (via subprocess). La skill Markdown usa los tools del MCP
  como su "cerebro" de datos. Un solo repo, todo coordinado.

  Trade-off: Mayor complejidad inicial de setup, pero cada subsistema se puede
  desarrollar en paralelo con SDD y la integración es limpia desde el día uno.

  ---
  Enfoque B — MCP-céntrico

  El MCP server es el hub total: contiene wrappers TypeScript del calc, llama a
  Showdown, y la skill es solo un thin prompt que enruta al servidor. Todo pasa
  por el MCP.

  Trade-off: Punto único de integración, fácil de consumir desde Claude Code.
  Pero el servidor se vuelve un monolito difícil de mantener, y si el MCP está
  caído no funciona nada.

  ---
  Enfoque C — Skill resiliente con componentes opcionales

  La skill Markdown tiene conocimiento experto embebido (funciona sin servidor).
  El MCP añade datos en tiempo real cuando está disponible. Python corre como
  CLI independiente.

  Trade-off: Funciona offline siempre. Pero la experiencia es fragmentada: el
  usuario tiene que saber qué herramienta usar cuándo.

  ---
  Mi recomendación es A — el monorepo integrado da la mejor experiencia final
  (routing automático funciona bien cuando todo se habla), y el SDD harness está
  diseñado exactamente para coordinar subsistemas paralelos de este tipo.
